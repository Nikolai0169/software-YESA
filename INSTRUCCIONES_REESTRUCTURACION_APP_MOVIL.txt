INSTRUCCIONES DE REESTRUCTURACIÓN DE app_movil PARA software-YESA

Objetivo:
- Reestructurar la carpeta `software-YESA/app_movil` usando como base la aplicación móvil completa de `software/software-main/app_movil`.
- Convertir la app YESA a una arquitectura de Expo Router con navegación por carpeta `app/`.
- Mantener los servicios, contexto y API existentes de YESA, corrigiendo errores menores y adaptando la configuración a Expo Router.

1. RESPALDO INMEDIATO
- Copia la carpeta actual `software-YESA/app_movil` a `software-YESA/app_movil_backup` antes de hacer cambios.
- Si hay archivos importantes (App.tsx, package.json, app.json, src) en el respaldo, mantenlos.

- Agrega `expo-router` y `react-is` si aún no existen.
- Conserva las dependencias de React Navigation que ya están instaladas.
- Asegúrate de que las dependencias Expo sean compatibles con `expo-router` y React 19.

5. COPIAR LA LÓGICA DE NAVEGACIÓN DEL PROYECTO BASE
- Usa `software/software-main/app_movil/app/_layout.tsx` como plantilla raíz.
- Usa `software/software-main/app_movil/app/(tabs)/_layout.tsx` para la barra de pestañas y los íconos.
- En las pantallas `index`, `carrito`, `explore`, etc., copia o adapta la lógica para mostrar los contenidos del carrito, catálogo, cuenta y navegación al checkout.

6. CONSERVAR Y CORREGIR LOS SERVICIOS EXISTENTES DE YESA
- El archivo `src/api/apiClient.js` es correcto en concepto, pero debe conectar bien con `src/utils/constants.js`.
- Revisa y corrige `src/utils/constants.js` para soportar `EXPO_PUBLIC_API_BASE_URL` y/o `extra.apiBaseUrl`.
- En `src/utils/storage.js`, corrige el error de nombre de función:
    - `storageGetItem` actual está definido 2 veces.
    - Cambia la segunda función a `storageSetItem`.
- Verifica que `authService.js` use las claves `STORAGE_KEYS` o `STORAGE_KEY` de forma consistente.

7. CORREGIR ERRORES EN authContext.js
- Cambia `export function authProvider({children})` a `export function AuthProvider({ children })` para seguir el patrón del proyecto base.
- Corrige el `Provider` para que use `value={value}` en lugar de `valuye={value}`.
- Asegúrate de exportar el hook y el provider con nombres usados por los componentes de la app.

8. AJUSTAR EL CONTEXTO Y EL ESTADO GLOBAL
- Si ya existe `carritoContext.js`, compáralo con `software-main/app_movil/src/context/CarritoContext.js`.
- Adapta el provider del carrito para funcionar con la nueva navegación y las mismas rutas de la tienda.

9. CREAR ARCHIVOS DE PÁGINA MÍNIMOS PARA ARRANCAR
- Para arrancar rápido, crea versiones simples de las pantallas que solo muestren un texto y un botón de prueba en cada ruta.
- Una vez se confirme la navegación, reemplaza esas pantallas con el contenido completo de YESA.

10. PRUEBAS Y VERIFICACIÓN
- Ejecuta en `software-YESA/app_movil`:
    npm install
    npm start
- Verifica que Expo arranca sin errores.
- Confirma que se puede navegar a la ruta principal `(tabs)` y a al menos una pantalla de admin o checkout.
- Comprueba que `apiBaseUrl` en `app.json` apunte al backend local correcto: `http://10.0.2.2:5000/api` para emulador Android o `http://<IP>:5000/api` en dispositivo real.
- Valida con una petición sencilla de login o catálogo que la conexión al backend funcione.

11. MANTENER COMPARACIÓN CON EL PROYECTO BASE
- Copia siempre como referencia:
    software/software-main/app_movil/app/_layout.tsx
    software/software-main/app_movil/app/(tabs)/_layout.tsx
    software/software-main/app_movil/src/utils/constants.js
    software/software-main/app_movil/src/utils/storage.js
    software/software-main/app_movil/src/context/AuthContext.js

12. NOTAS IMPORTANTES
- No mezcles `App.tsx` tradicional con Expo Router. Si usas `expo-router/entry`, la navegación se gestiona desde `app/_layout.tsx`.
- El código actual de YESA usa `app_movil/src/api/apiClient.js` con axios y atributos `STORAGE_KEYS`; deja esa lógica y adapta la base URL.
- Para una reestructuración ordenada, primero confirma la instalación y la navegación básica, después migra la lógica de pantalla.

Resultado esperado:
- `software-YESA/app_movil` debe convertirse en una app Expo Router completa.
- La carpeta `app/` debe contener todas las rutas de cliente y admin.
- `src/` sigue siendo la capa de servicios y contexto, ahora integrada con la navegación.
- El archivo `App.tsx` y la carpeta `src/` original de YESA deben ser refactorizados o archivados en caso de ser reemplazados.
